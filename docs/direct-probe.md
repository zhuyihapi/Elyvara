# M0 直连测试

从项目根目录运行 `npm run check` 和 `npm run smoke:mesh`。后者启动独立回环 Go 服务及四个独立的 Electron 客户端窗口，验证邀请审批、六对 host 路径、一个发送端向三人发送合成视频、脱敏导出和离房清理。测试自动关闭自己的窗口和服务。

人工测试用 `npm run start:signaling` 启动回环服务，然后用 `npm start` 启动客户端。跨机器测试需要用户可达且证书可信的 `wss://…/ws` 端点。STUN 地址可选，格式为 `stun:host:3478` 或 `stun:[IPv6]:3478`。点击「检查 STUN」发起单独的 ICE 收集。观察到 srflx 是候选发现证据，具体映射和好友连通性仍需分别测试。

每对成员按 peer ID 决定 offer 发起方。对端按代次缓存先到候选，应用描述后逐条加入。发起方最多尝试两次替换连接，失败状态保留供诊断。信令断开会清理当前房间，重新连接后由用户重新加入。发送端主动启动 640×360、15 fps 的测试图案，退出或断开时停止轨道。

候选路径依据 WebRTC transport 统计中的选定候选对。路径变更时重置速率基线，首个样本和缺失字段显示未知。RTT 为候选对往返时间。选中 relay 会关闭该连接。代理设置和疑似虚拟网卡只作为线索，实际出口保留未知。可参考 [WebRTC 统计标准](https://www.w3.org/TR/webrtc-stats/)。

点击「导出脱敏诊断」保存当时的 JSON 摘要。摘要只包括会话状态、编号、候选类型、地址族、协议、速率、RTT、STUN 观察结果和代理线索。邀请令牌、昵称、地址、SDP 和候选内容均留在当前会话，参与直连的对端可能看到 ICE 候选地址。回环验证为开发证据，跨线路连通性和画质以 M0.5 记录为准。
